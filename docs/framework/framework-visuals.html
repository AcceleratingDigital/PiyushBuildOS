Unified SDLC Framework — Deployment Topology

Team members, shared services, per-person vs shared environments · Tailscale mesh · LiteLLM model tier

Per-person (private)

  • • Local git checkout
  • • Optional local agent daemon (sandboxed)
  • • Oversight surface (Hermes GUI / Slack)
  • • Nothing stateful — state lives in shared services

Shared services (run once)

  • • Orchestrator + tracker ingestion
  • • Sandbox farm (ephemeral per-task containers)
  • • State tier: Postgres + MinIO + Redis
  • • Model tier: LiteLLM on GPU node
  • • Release pipeline: one canonical build machine

Human gates (named at kickoff)

  • • PO — requirements, priorities, ship/no-ship
  • • Architecture — specs, ADRs, system impact
  • • Security — threat models, scan exceptions
  • • QA — release readiness, traceability
  • • UX — design doc before story starts

Hard boundaries

  • • No agent or human pushes to main — PR only
  • • AI review = evidence, never approval
  • • Releases built ONLY by canonical pipeline
  • • Session memory is cache; state tier is truth

Requirements Flow — intake to release, with human gates

Every artifact versioned in the repo · IDs trace the chain · gates are named humans, not role abstractions

Repo = the contract

  • • Requirements, specs, ADRs live in git, PR-reviewed
  • • Tracker cards hold status + links, not content
  • • Retire "task notes are the contract"

Gates are people

  • • Each gate = named human, assigned at kickoff
  • • AI review = cited evidence, never approval
  • • Small-change lane: pre-delegated approval only

Agents run the middle

  • • Gate-contract validation before each stage
  • • Evidence to state tier, not self-reports
  • • Fail → status-blocked + Slack alert

Reality closes the loop

  • • Device confirmation completes a release
  • • BUG/FEATURE findings become tracked work
  • • Metrics + postmortems tune the system monthly
