## Status page (status.html) — DATA-DRIVEN

The status page is split into files in `~/code/hos-site/`:

1. **status.html** — static layout, CSS, filter bar, JS. **NEVER modified by agents.** Loads data via `<script src="status-data.js">` (works on file://) with `fetch('status-data.json')` fallback for web servers.
2. **status-data.js** — JSONP wrapper (`var __statusData = {...}`). Generated by `generate-status-data.py`.
3. **status-data.json** — raw JSON. Generated by `generate-status-data.py`.

**To update the status page:** Run `python3 ~/code/hos-site/generate-status-data.py` — it queries Asana and writes BOTH status-data.json AND status-data.js. The HTML is untouched.

## Doc pages

Feature doc pages live in `~/code/hos-site/docs/`. When a feature ships, generate a doc page from the template and link it in status-data.json. Feature names on the status page are clickable links to their doc pages when doc_url is set.

## Update triggers

- New skill built → add doc page in ~/code/hos-site/docs/ + regenerate status-data.json
- Skill shipped → update badge in status-data.json (regenerate)
- Feature status changes → regenerate status-data.json (NEVER edit status.html)
- Release published → update footer version, add release page in ~/code/hos-site/releases/

## Design system

- CSS variables defined in `design-system.html` and each page's `<style>` block
- Light/dark mode via `prefers-color-scheme`
- Fonts: system UI, serif for lede text, mono for code
- Colors: ground (#EDE8DF light / #0F1216 dark), structure (#44607F), accent (#B4741E), ok (#1E6E5A)
- Badges: shipped (🟢), in progress (🟡), planned (⚪), 0.9 build (🚧)
